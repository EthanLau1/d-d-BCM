## 第一部分：Demo 极简打开与体验方式

本 Demo 位于桌面文件夹：`Desktop/BCM-Web-Demo/`，专为向外部展示打造，**零外部环境依赖、零链上依赖、纯静态即开即看**。

### 方式一：直接双击打开（最快）
* 直接双击打开 `BCM-Web-Demo/index.html` 即可在任意系统浏览器中浏览所有展示板块与试玩功能。

### 方式二：一键启动本地演示服务（推荐，最佳动效与海报导出体验）
* **Mac 电脑**：直接双击 `start_demo.command`，会自动启动轻量本地服务并弹开浏览器访问 `http://localhost:8888/#original`。
* **Windows 电脑**：直接双击 `start_demo.bat`。
* **命令行运行**：
  ```bash
  cd ~/Desktop/BCM-Web-Demo
  python3 -m http.server 8888
  # 浏览器访问: http://localhost:8888
  ```

### 1. 原创声明 (Original Statement) · 艺术与版权边界
清晰向外界与社区界定 BCM 机车的两个组成部分：
1. **原创车架（版权所有）**：包含车身轮廓、车架管梁、引擎、把手等机械骨架，由团队耗时 3 年原创焊接设计，受版权法保护。
2. **瓶盖元素（CC0 处理）**：取自市场上真实存在的饮料罐/瓶盖符号。作为对商业代言误解的主动隔离，团队以 CC0（放弃版权）处理瓶盖部分，并鼓励全球社区自由二创。

### 3. 遇到的技术难点与解决方案 (Technical Challenges & Solutions)

#### 难点 1：链上艺术持久性与发售前“防抓包防枚举”的冲突 (On-chain Art vs. Pre-reveal Secrecy)
* **挑战**：
  如果为了追求纯粹的链上艺术而在发售前把全部 7,700 张高精图层上传至公开网络或公开合约，黑客或脚本可以通过遍历枚举提前获知所有未开奖 NFT 的外观与稀有度，导致正式发售失去神秘感与稀缺惊喜。
* **解决方案**：
  采用**“渐进式解锁与哈希承诺”**机制：
  1. 发售前仅将全部资产包的哈希承诺上链证明团队未被篡改；
  2. 公开试玩台（Playground）仅投放中立工程轮组与 6 款常规车架，**严格雪藏 UR #8 单车等旗舰图层**；
  3. 每日铸造或揭晓一个作品，才向公开链上和 Playground 解锁对应部件。

#### 难点 2：高精重叠素材在前端实时拼装的性能与兼容性 (Multi-layer Real-time Compositing)
* **挑战**：
  每个机车涂装原始切片分辨率高达 2048×2048，若在浏览器端直接频繁加载多个透明 PNG 大图并进行 Canvas 像素级重绘，在低配移动设备或多标签页下容易发生卡顿或渲染撕裂。
* **解决方案**：
  采用**三层视窗分离架构**（独立底图层 + 固定独立轮组层 + 动态车架层），对试玩切片实施 WebP/PNG 压缩与视网膜尺寸预裁切；利用 CSS 硬件加速与离屏 Canvas（Offscreen Canvas）异步合成技术，实现毫秒级平滑换装与一键海报下载。
